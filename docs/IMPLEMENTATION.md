# Implementation status

October 28, 2026

The local checkpoint slice implements parts of the design, not the entire proposed production platform. The design documents remain the future direction; this status file and TEST_REPORT describe present behavior.

## Implemented

Current visual-awareness update supersedes the one-image-only companion descriptions below. Camera-on idle observation sends up to six chronological frames from the latest eight seconds to Muse, targeted every six seconds with one in-flight job. Structured scene/activity/change summaries stay in session memory and inform the next conversation. Questions also include frame history. Recent local pose events are supplied as estimated evidence. Confidence and cooldowns limit proactive speech. Voice interrupts background observation; stopping camera cancels it and clears visual context. Local MediaPipe Pose Landmarker Lite, pinned SDK/model, performs pose tracking in a worker. Fast person/hand-rise responses complement general Muse activity interpretation; they are not the only recognized activities. See VISUAL_AWARENESS.md for rates, limitations and verification.


Latest voice implementation supersedes push-to-talk below: `shared/voice-turn.ts` locally detects utterances from a persistent AudioWorklet microphone session. Silence dispatches nothing; completed turns are converted to bounded mono WAV and transcribed by Meta. `POST /api/agent/stream` forwards only visible Responses text events to the browser, with a terminal validated response or sanitized error. Complete phrases are spoken while more text arrives. A new detected utterance can interrupt reply generation/read-aloud, await the cancellation epoch, and start another turn. End voice, background, disconnect and unmount release microphone resources. Opening camera starts voice too when a model is connected.

Companion snapshot replies now require fresh images at dispatch but retain delayed answers, prefixed and labeled as captured-image observations. They never become live activity verification. The separate legacy checkpoint `respond` path retains its strict freshness rule. All runtime adapters remain fixture-verified rather than agent-tested against live credentials.


Current companion-first update supersedes the mandatory source form below. Home shows the blue star, camera controls and typed/hands-free conversation. Optional Instructions in the header takes one public HTTPS URL. Muse Responses with built-in web search returns cited guidance; a missing completed search or citations produces a clear failure. Muse Voice Transcribe accepts a bounded 15-second mono WAV; the browser reads Muse Spark's answer aloud. Camera-on messages each send one fresh still. Video is not streamed continuously; microphone capture stays active during a voice session. Conversation and the current researched summary stay in session memory, with New task clearing context and canceling pending work. The optional illustrated checkpoint example retains its reviewed-source and progress controls.

These provider paths are fixture-tested, not live-verified. There is no direct unrestricted fetch of user links. Provider/key details have moved to About to keep the key dialog minimal. No actual API credentials or paid calls were used.

Stage-0 baseline instrumentation (Task 0, October 28, 2026): numbers-only timing logs, no behavior change. `shared/timing.ts` validates and logs voice-turn records (`capturedStartMs`, `asrFinalMs`, `modelFirstTokenMs`, `playbackStartMs`) and observation records (submit/return, frame count) to the browser console; `server/engine.ts` logs per-lane server spans to stdout. No transcript, frame, URL, or key content can pass the strict schemas. Barge-in latency, observation/server failure spans, and gesture-detection marks are not instrumented yet. A barge-in echo guard (`src/barge-guard.ts`, 500 ms after each spoken phrase starts) drops probable speaker-echo turns instead of interrupting the reply; later voice barge-ins and the explicit interrupt control still work. Speech output unlocks platform TTS inside the voice-chat tap (resume plus one silent utterance), resumes a paused synthesizer before each phrase, assigns a preferred localService voice once voices load, and chunks phrases past 200 characters, for iOS Safari where speech otherwise never plays. `docs/SPIKE.md` holds the unmeasured baseline table, the run procedure, and the officially verified Muse Voice Transcribe realtime and SAM 3.1 contracts with explicit unknown lists.

Transcript-only voice, faster camera voice turns, friendly tone (October 30, 2026, branch `task/a-realtime-asr`, unmerged): voice messages now show exactly the transcript — the WAV-fallback note is removed (fallback stays diagnosable via server transcribe timings). Voice robustness: adaptive VAD, confirmed barge-in, no churn (October 30, 2026, branch `task/a-realtime-asr`, unmerged): background noise no longer floods the session — the detector learns a 5 s noise floor (300 ms lag so speech never pollutes it) and requires voice 4x above it, so steady noise fires at most one turn and then goes quiet. Speech-start still stops local playback within ~100 ms per the design target, but server invalidation (epoch bump) and lane open now wait 300 ms for turn confirmation, so pops and noise bursts never abort in-flight work or storm stream opens; the client buffers pre-open audio and flushes on `opened`, so confirmed barge turns lose nothing. Streaming endpointing is 500 ms with mid-thought extension from live partials (WAV stays 850 ms); routine voice-lane CANCELED lines are demoted to debug. Covered by detector noise/endpointing units, client pre-open buffer units, and the unchanged barge/interrupt/echo e2e.

Speech cut-off and sync fixes (October 30, 2026, branch `task/a-realtime-asr`, unmerged): barge-ins no longer destroy the reply they interrupt — `SpeechQueue` gains `softStop()`, which halts audible output instantly while preserving the unheard queue (plus any partial buffer), and `resume()`, called when the transcript proves to be speaker echo so Glint continues where it stopped; only a genuine turn hard-cancels. `cancelWork()` takes a soft flag (skipping the interrupted badge on the soft path), `interrupt()` splits out a `pauseServer()` step used by the 300 ms barge confirmation, and `send()` soft-stops before the echo check and hard-stops after it. Long replies are chunked past 200 characters only on iOS, where long utterances stall; desktop speaks whole sentences, removing per-boundary gaps and subtitle flicker. Voice holds a screen wake lock while enabled (released on end-voice) so the phone sleeping can no longer kill speech mid-reply. Covered by soft-stop/resume/chunking units; barge/interrupt/echo/mute e2e unchanged and green.

Interruption parity: resume on dropped turns, semantic endpointing (October 30, 2026, branch `task/a-realtime-asr`, unmerged): a detector turn that ends without audio (under 200 ms voiced — pops, clicks, short bursts) no longer kills the reply it interrupted. The microphone reports whether each ended turn produced audio, and `CompanionHome` resumes the soft-stopped speech queue on dropped turns; sent turns still resolve through the echo verdict. Endpointing is now semantic in both directions: the continuation signal list grows from fillers to trailing function words (conjunctions, subordinators, prepositions, articles, auxiliaries, `than`, arithmetic words, cut-off dashes, colons), and clearly finished partials (12+ chars with terminal punctuation) end after a 300 ms window instead of 500 ms — short acknowledgments stay patient so stale partials can't split "Yes, and…". The detector accepts a live end-silence window evaluated per frame. Covered by a dropped-burst resume e2e (180 ms blip pauses then resumes read-aloud with zero sends) plus continuation/completion/dynamic-window units. ML VAD (Silero) evaluated as the next slice, not yet implemented: see SPIKE.md.

Neural VAD: local Silero v6 OR-fused with energy (October 30, 2026, branch `task/a-realtime-asr`, unmerged): turn detection now runs a local Silero v6 model (MIT, `public/vad/silero_vad.onnx`, hash-pinned by `scripts/prepare-vad.mjs` like the vision model) on ONNX Runtime WASM single-threaded SIMD (`onnxruntime-web` pinned to 1.16.3, the last version shipping a non-threaded build — the app is not cross-origin isolated and COEP would break API fetches; assets copied to gitignored `public/vad/runtime/`). `src/ml-vad.ts` resamples mic audio to 16 kHz, runs 512-sample windows with the 64-sample context prefix v6's frontend requires (plain windows score ~0 — verified during development), and thresholds at 0.5; the verdict is OR-fused into `VoiceTurnDetector`, so ML can only add detections (quiet speech in noise), never veto energy. Model load is lazy (own bundle chunk) and any failure degrades silently to energy-only; `localStorage glint-ml-vad=0` is the kill switch. Proves itself: a quiet-JFK-clip e2e detects a turn with ML on and nothing with ML off, plus a missing-assets fallback e2e and resampler/fusion/stub-runner units.

Noise robustness hardening (October 30, 2026, branch `task/a-realtime-asr`, unmerged): neural-VAD load/inference failures are now visible — `useMicrophone` reports ML status and the UI shows "Neural voice detection unavailable (reason); using basic detection" instead of failing silently — plus a plain-WASM fallback build is vendored for devices without SIMD (ORT auto-selects). Turns that transcribe empty (WAV and streaming) now resume an interrupted reply instead of answering silence. The interruption e2e uses Meta-realistic mocks (short follow-up audio transcribes empty), so both the drop and sent branches converge on resume with zero agent turns; a second deterministic test pins resume-on-empty with a 400 ms burst. A committed real-model test pins Silero's response classes (speech high, silence/noise low). Known characteristics found while stabilizing: pure tones hallucinate Silero alignment-dependently (verified in Node), and browser noise suppression eats white-noise fixture bursts before detection — hence tone blips plus the characterization test.

Speaker lock: local WeSpeaker verification with async gating (October 30, 2026, branch `task/a-realtime-asr`, unmerged): voice turns are verified against an enrolled owner voiceprint entirely on-device. `src/speaker-id.ts` embeds each turn's audio with WeSpeaker ResNet34-LM (Apache-2.0, `public/speaker/wespeaker_resnet34_LM.onnx` vendored 25.3 MB, hash-pinned by `scripts/prepare-speaker.mjs`) over a Kaldi-compatible 80-bin fbank frontend with per-utterance mean normalization (validated as required: without CMN same/cross-speaker scores overlap) on the shared ONNX Runtime WASM build; cosine similarity below 0.32 rejects. Enrollment is explicit (two 4 s samples with an inaudible-sample guard, averaged and L2-normalized into `localStorage`), and verification runs beside transcription so the owner never waits: a settled stranger verdict aborts before any server call, a mid-flight verdict kills the turn and resumes interrupted speech like any false trigger, and short turns, failures, and missing enrollment all fail open. `localStorage glint-speaker-lock=0` is the kill switch. Model choice and threshold come from real-model validation (same-speaker ≥0.67 clean, strangers ≤0.25, white-noise floor mapped to ~5 dB); voiced-only frame selection was tested and disproven as a robustness help. Covered by frontend/scoring/queue/storage units, a committed real-model characterization test (same-speaker high, noise/sine low, short clips verify, bit-determinism), and four e2e tests behind a mocked scorer (owner answered plus fast/slow stranger ignored, stranger barge resumes the reply, enrollment on/off, streamed settled-verdict fast path).

Streaming Glint voice: server-side Kokoro neural TTS (October 30, 2026, branch `task/a-realtime-asr`, unmerged): spoken replies now use one consistent natural voice instead of per-device robot speech. `scripts/prepare-tts.mjs` (wired into postinstall/predev/prebuild) fetches the sherpa Kokoro int8 multi-lang pack (109 MB model + 27 MB voices + lexicon/tokens, hash-pinned, `csukuangfj/kokoro-int8-multi-lang-v1_0` commit `57adb37`) into gitignored `.data/tts/` and warns fail-open on any download failure. `server/tts-kokoro.ts` loads it through the prebuilt `sherpa-onnx-node` binding (non-blocking `generateAsync`, 24 kHz, af_heart speaker id 3, lexicon-only G2P so no GPL espeak bytes ship) behind `getServerVoice()`, which returns a deterministic `MockVoice` under `GLINT_TTS_MOCK=1`, null under `GLINT_NEURAL_VOICE=0` or missing files, shares one load across concurrent first requests, warms up beside server boot, and verifies with a synth before caching. `POST /api/agent/stream` with `voice: "neural"` loads the voice beside the LLM stream (early deltas buffer, text never waits), announces `voice` neural/none, synths each `SentenceStream` sentence (`shared/sentence-split.ts`, abbreviation/decimal/quote aware) through a FIFO `TtsStream` that emits ordered `audio` events (base64 PCM16 + text + `[glint-timing]` tts spans) or per-sentence `audio-error`, drains before `voice-done`, and cancels on client abort or converse failure. `src/voice-player.ts` plays sentences gaplessly via AudioContext, falls back to device speech per failed sentence, mirrors the SpeechQueue stop/resume/unlock surface so barge-in and the speaker lock treat both voices alike, and announces each sentence via `glint-voice-audio` for tests and tooling. `CompanionHome` requests neural by default, keeps robot speech for deltas only when the reply is not neural, records the mode on `document.body.dataset.voiceMode`, and `localStorage glint-neural-voice=0` is the kill switch; text chat (`App.tsx`) sends no voice flag and is unchanged. Model choice and latency (RTF ~1.0 whole-sentence on laptop CPU, first audio after the first sentence synths) come from real-model probing; see SPIKE.md Part E. The first phone run caught a synth pile-up under barge churn (overlapping native synths slowed each other 3.3 s → 10.6 s per sentence, so audio arrived generations late and the client correctly dropped it as stale): all requests now share one FIFO synth lane (`serializeVoice`), and `cleanSpeakText` folds curly quotes/dashes to ASCII plus expands the seven contractions proven missing from the lexicon (what's, what'd, that's, here's, should've, would've, 'til) so words stop skipping. The second phone run caught soft barges aborting the post-text audio drain (reply spoke its first sentence, then the tail died with the UI wedged on "Replying…"): soft cancelWork no longer aborts or invalidates a drain, only a genuine new send supersedes it (bump, abort, silent finalize), and the SSE size caps grew to audio scale (20 MB stream, 4 MB event) so long replies can't trip the shared reader. The player now resumes a suspended AudioContext on every sentence (mobile lock-screen/tab-switch wedge), reports playback state to an on-screen voice note (tap to resume), and cross-turn memory is pinned by an HTTP test that counts history turns across two requests. Covered by splitter/stream/player/cleaner/serializer/agent-stream units, a committed Kokoro real-model test, three HTTP route cases, and a mocked-SSE browser spec; the companion suite pins robot speech.

## Deliberate first-slice boundaries

Local device sessions are not account login. SQLite is a single-process development store, not the proposed production PostgreSQL deployment. Optional URL research uses Muse built-in search; direct PDF/image manual extraction is not present. No GPU tracking, native clips, temporal action model, LiveKit, MediaPipe, Docling, Supabase, Rive, or hosted deployment is connected. Browser TTS is an optional local output experiment, canceled by text focus/input and an explicit interrupt button. Key price estimates remain unconfigured; the UI shows a call allowance rather than invented prices.

Camera samples stay local until a camera-on message or explicit view check selects one JPEG. Frame eviction is normal checkpoint-buffer behavior, not preservation of all task events. No complete action coverage is claimed. The legacy checkpoint path suppresses long model responses as stale. Companion image questions instead retain delayed snapshot answers, without claiming present-time verification. User-reported completion is never relabeled visually verified. Foreground/background limitations remain visible and capture stops when the page hides.

## Before a production label

See the release gates in TODO.md and GLINT_DESIGN.md. In particular, test the actual key/model through the application, choose the first authoritative manual, calibrate error/false-alert metrics on a held-out task set, prove recovery and privacy across deployment instances, fund service costs, review public security and deletion, and complete real-device 60/90-minute soaks and load tests. No deployment, model accuracy, sustained thermal/battery behavior, or production certification is implied by local checks.
